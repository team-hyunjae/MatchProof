## 프로젝트 소개 (Project Overview)

MatchProof는 결혼정보업체가 신청자의 소득·혼인 관련 원본 서류를 수집·보관하지 않고 가입 조건의 충족 여부를 확인하도록 만든 Midnight 기반 DApp입니다. 가입 심사에 필요한 것은 일정 소득 기준을 충족하는지, 확인 기준일에 혼인 중이 아닌지와 같은 조건입니다. 이를 위해 상세 서류 사본을 반복해서 주고받으면 신청자의 정보 노출과 업체의 보관 부담이 커집니다. MatchProof는 검증기관의 자료 확인과 업체의 가입 심사를 분리해, 업체에 전달되는 정보를 줄입니다.

사용 흐름은 자격 발급, 심사 요청, 신청자 동의와 증명, 업체의 결과 확인으로 이어집니다. 검증기관이 신청자 키에 연결된 자격을 발급하면 신청자는 이를 암호화된 보관함에 저장합니다. 업체가 심사 요청을 만들면 신청자는 수신 업체·조건·공개 범위·기한을 확인하고 동의한 뒤 영지식 증명을 제출합니다. 업체는 신청자의 자격 파일이나 정확한 소득액을 받지 않고 체인에 확정된 조건 충족 결과를 조회합니다.

데모에서는 ‘2025년 연간 소득 5,000만 원 이상’, ‘자료 확인 기준일에 혼인 중이 아님’, ‘요청 종료까지 자료 확인 후 7일 이내’라는 가상 정책을 사용합니다. 조건 충족 사례와 소득 미달 거절 사례를 시연하며, 업체에는 구체적인 실패 사유를 전달하지 않습니다. 현재 구현은 모의 검증기관과 가상 자료를 사용하는 Midnight Local Devnet(`undeployed`) 프로토타입입니다.

## Midnight 구현 포인트 (Midnight Implementation)

Midnight의 공개 원장과 Compact 영지식 증명 회로를 활용해 비공개 자격 정보가 공개된 심사 정책을 충족하는지 검증했습니다. Compact 계약은 자격 발급(`issue`), 업체의 심사 요청 등록(`openRequest`), 신청자의 조건 증명(`proveEligibility`)을 처리합니다.

검증기관은 신청자 키에 연결된 자격의 commitment를 Merkle tree에 등록합니다. Commitment는 자격 내용과 난수를 해시로 결합한 등록값으로, 정확한 소득 등 상세 값은 공개 원장에 기록하지 않습니다. 발급과 요청 등록은 각각 계약에 등록된 기관·업체의 비밀키 소유를 확인한 뒤 실행됩니다.

조건 증명 회로는 다음을 함께 검증합니다.

1. 제출한 자격이 등록된 Merkle tree에 포함되어 있는지
2. 신청자가 자격에 연결된 비밀키를 소유하며, 심사 요청이 동일한 배포·신청자·요청 난수에 연결되어 있는지
3. 소득 연도와 최소 소득 기준을 충족하고, 확인 기준일에 혼인 중이 아니었는지
4. 요청 종료까지 자격의 유효기간과 자료의 최신성 조건이 유지되는지
5. 요청이 블록 시간 기준으로 유효하며, 이미 승인된 요청을 재사용하지 않는지

정확한 소득액, 자격에 담긴 혼인 상태 값과 확인일, 비밀키·난수는 비공개 증명 입력으로 처리합니다. 공개되는 것은 배포 식별값, 기관·업체의 키 해시, 자격 commitment와 Merkle tree 상태, 심사 정책, 요청 식별값·시간 범위, 승인 기록입니다. 신청자 앱은 명시적 동의 후 증명을 시작하고, 체인 확정 이후에만 성공을 표시합니다. 업체·심사위원은 지갑이나 신청자 자격 파일 없이 체인 밖 인덱서를 통해 동일한 공개 결과를 조회합니다.

이 구조는 업체가 상세 개인정보를 축적하지 않고 필요한 조건을 확인하도록 합니다. 다만 실제 자료의 진실성은 발급기관의 확인에 의존하며, 현재 증명 서버는 비공개 입력을 처리합니다. 공개 정책과 승인 기록이 개인과 연결되면 조건 충족 사실을 추론할 수 있습니다. 요청의 최대 10분 유효기간은 사용을 제한하는 장치이며, 만료 후에도 체인 기록은 남습니다. 현재 구현에는 삭제·즉시 철회 기능이 없습니다.
