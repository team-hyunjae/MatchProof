# MatchProof 데모 영상 촬영 가이드

**2026-09-27 현재: 한국어 녹음과 영어 자막을 결합한 4분 52초, 1080p 편집본을 완성했다.** [완성 파일과 검수 내용](video-delivery.md), [최종 영어 SRT](demo-subtitles.en.srt)를 참고한다. 업로드와 최종 제출은 아직 수행하지 않았다.

무음 초안은 4분 30초였으며, 녹음 속도를 유지하기 위해 일부 설명 화면을 늘렸다. 로컬 완성 파일은 `artifacts/recordings/2026-09-27/matchproof-demo-ko-en.mp4`다. 아래 녹화 방법은 재촬영 시 참고용이다.

## 1. 녹화 방법

Mac 기본 화면 기록으로 충분하다. `Shift + Command + 5`를 누르고 **선택 부분 기록**을 선택한다. **옵션**에서 사용할 마이크와 저장 위치를 지정한다. 먼저 10초 정도 시험 녹화해 목소리와 글자 크기를 확인한 뒤 본 촬영을 시작한다. 종료는 메뉴 막대의 기록 중단 버튼을 사용한다. [Apple 공식 화면 기록 안내](https://support.apple.com/ko-kr/102618)

브라우저가 들어갈 가로 16:9 영역을 잡고, 최종 편집본은 1920×1080을 목표로 한다. 실제 녹화 해상도는 선택 영역에 따라 달라진다. 글자가 작으면 브라우저를 확대한다. PPT 전체 그림도 같은 녹화 영역 안에서 보여주거나, 제공한 PNG를 편집기에 넣는다.

저장 위치는 `~/devel/ai/MatchProof/artifacts/recordings/`를 사용한다. 이 폴더는 Git에서 제외되므로 원본 동영상을 실수로 저장소에 올리지 않는다. 파일 예시는 `matchproof-take-01.mov`, 최종본은 `matchproof-demo.mp4`다. 실제 생성된 파일만 최종 제출 자료로 표시한다.

두 사람이 촬영을 나눈다면 한 사람이 화면을 조작하고 다른 사람이 설명·녹화를 확인해도 된다. 이는 발표 역할 분담이며 개발 기여 설명을 추가할 필요는 없다.

## 2. 녹화 전에 완료할 준비

1. 개발 서비스가 실행 중인지 `npm run doctor:network`로 확인한다. `npm run demo` 실행 후 `MatchProof DEMO READY`를 기다린다. 준비 이후 30분 세션 안에서 촬영한다. 새 세션이 필요하면 녹화 전에 재시작하고 페이지를 새로고침한다.
2. 검증기관·신청자·업체 탭을 구분해 둔다. 보관 암호 입력과 같은 배포 연결을 끝낸다. 전체 설치·컴파일·키 입력 과정은 본 영상에 넣지 않는다.
3. 성공용 자격을 미리 발급한다. 가상 소득은 2025년 6,500만 원, 확인 기준일에 혼인 중이 아님이다. 신청자에게 자격을 가져와 **나만 보는 가상 자료**가 보이는지 확인한다.
4. 실패 시연용 3,000만 원 자격을 미리 준비하되, 성공 시연 전에 신청자 자격을 실패용으로 바꾸지 않는다. 정확한 파일 내용·비밀키·보관 암호를 녹화 화면에 펼치지 않는다.
5. 지갑을 연결하지 않은 별도 브라우저/프로필에 공개 조회 화면을 준비한다. 발표자 기기에서의 별도 조회이며, 다른 물리 기기 재현이라고 설명하지 않는다.
6. 이미 만료된 요청을 한 개 준비한다. 만료 장면에서는 과거 요청임을 밝힌다. 새 요청을 열어 둔 채 설명 연습을 오래 하지 않는다.
7. 알림과 관련 없는 탭을 정리한다. 화면에 개발 네트워크·가상 자료·자동 서명 테스트 지갑이라는 범위가 보이게 하거나 내레이션으로 먼저 설명한다.

**심사 요청은 촬영 직전에 만든다.** 새 증명 장면을 다시 찍을 때는 승인된 요청을 재사용하지 않고 새 접수번호·새 요청을 만든다. 같은 개발 지갑을 쓰는 `matchproof:smoke`를 녹화 중 함께 실행하지 않는다.

## 4. 편집과 영어 자막

기본 도구로 진행하려면 **Mac 화면 기록 → QuickTime에서 불필요한 구간 정리 → YouTube에 영상과 영어 SRT 추가** 순서가 간단하다. QuickTime의 **보기 → 클립 보기**, **편집 → 클립 분리**로 대기·실수 구간을 분리하고 삭제할 수 있다. 원본은 보관하고 편집본을 별도 이름으로 저장한다. [Apple 클립 편집 안내](https://support.apple.com/ko-kr/guide/quicktime-player/qtpa2d90df3d/mac)

YouTube를 사용할 경우 Studio에서 영상을 선택한 뒤 **자막 → 언어 추가 → 영어 → 추가 → 파일 업로드**로 시간 조정이 끝난 SRT를 넣는다. YouTube는 UTF-8 `.srt`를 지원한다. 한국어 원음의 자동 자막과 준비한 영어 번역 자막을 구분한다. [자막 추가 안내](https://support.google.com/youtube/answer/2734796?hl=ko) · [지원 형식](https://support.google.com/youtube/answer/2734698?hl=ko)

- 긴 대기를 잘랐다면 설명 자막이나 내레이션에 실제 측정한 대기 시간을 넣는다. 실제 측정 전 임의의 초를 넣지 않는다. 예: `Proof generation and confirmation: [실측값] s`.
- 증명 시작, 확정 메시지, 업체의 같은 요청 조회는 연결해서 보여준다. 과거 성공 화면을 새 요청의 성공처럼 편집하지 않는다.
- 최종 영상에는 [장면별 한국어 녹음](voiceover-ko.md)과 [발화 기준 영어 SRT](demo-subtitles.en.srt)를 사용했다. 기존 대본과 자막 초안은 참고용으로 보존한다.
- 13개 한국어 녹음을 결합했다. 확정 전 성공으로 설명하지 않도록 음성과 자막을 검수했다.
- 영어 자막이 버튼이나 거래 상태를 가리지 않게 배치한다. 화면 아래에 여백을 두거나 자막 위치를 조정한다. 업로드 플랫폼의 자막 트랙 또는 영상에 삽입한 자막 중 하나를 선택한다.
- 마지막에 10분 만료가 체인 기록 삭제가 아님을 설명한다. 자료 진위는 기관의 확인을 신뢰하며, 증명 서버가 비공개 입력을 처리한다는 설명을 유지한다.

## 5. 업로드 전 확인

- [ ] 처음 보는 사람이 각 화면의 역할을 구분할 수 있다.
- [ ] 기관의 자격 파일과 업체의 요청 파일을 구분한다.
- [ ] 성공 장면이 같은 배포·요청으로 이어지고, 확정 후 공개 조회가 나온다.
- [ ] 거절은 제출 전 검사라는 점을 설명한다. 실패 거래가 채굴됐다고 표현하지 않는다.
- [ ] 정확한 소득이 보이는 화면은 신청자/기관 화면이고, 업체 화면에는 없다.
- [ ] 키·비밀번호·비공개 JSON·관련 없는 개인정보가 보이지 않는다.
- [ ] 영어 자막의 숫자와 시간, 말하는 내용이 실제 화면과 맞는다.
- [ ] 공개 또는 일부 공개 영상 링크를 로그아웃 상태에서 끝까지 재생해 본다.
- [ ] 확인한 링크를 [제출 설명](project-description.md)에 넣고 [체크리스트](checklist.md)를 갱신한다.

영상 링크가 준비되기 전에는 `localhost` 주소나 자막 초안을 영상 제출물로 대신 기재하지 않는다.
