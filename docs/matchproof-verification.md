## 실제 브라우저 화면을 통한 개발 네트워크 실행

Production preview `http://127.0.0.1:4180/matchproof`에서 Playwright로 역할별 화면을 조작했다. 지갑 연결에는 공식 `DAppConnectorWalletAdapter`를 로컬 검사 도구로 연결했다. **실제 지갑 확장의 승인창을 검증한 것은 아니다.** 공개 local genesis 지갑으로 실제 거래를 서명·제출했으며, 화면이나 체인 응답을 가짜 성공으로 바꾸지 않았다.

확인한 흐름:

1. 업체 등록값 생성 → 기관의 브라우저 배포.
2. 신청자 배포별 키 생성 → 기관의 브라우저 발급 → 자격 파일 다운로드.
3. 업체 요청 생성·확정 → 요청 파일 다운로드.
4. 신청자가 두 파일을 브라우저에서 가져오고 체인·키 결합 확인.
5. 신청자 키·자격증명·요청을 새로고침 후 암호화 보관함에서 복구.
6. 동의 전 제출 버튼 비활성화, 새로고침 후 동의 재확인.
7. 신청자 화면에서 ZK 증명·거래 확정 후 재제출 버튼 비활성화.
8. **지갑 연결도 신청자 보관함도 없는 새 브라우저**에서 공개 인덱서를 조회해 승인 1건 확인. 심사 행에 정확한 가상 소득액이 없음.

앱의 public ledger 구조·파일 경계·화면 결과를 확인한 것이다. 모든 네트워크 메타데이터에 대한 익명성 감사나 전체 트래픽의 비밀정보 누출 검증을 수행했다고 주장하지 않는다. 역할은 같은 장치의 다른 암호화 namespace로 분리했고 수수료 지갑은 하나다. 독립 물리 기기·서로 다른 지갑의 연결 가능성은 후속 검증 대상이다.

화면은 1440px 데스크톱과 390px 모바일에서 가로 넘침이 없음을 확인했다. 신청자·업체 전체 화면 캡처는 `output/playwright/matchproof-*.png`에 있다. 공개 조회 브라우저에서 JS 오류는 없었고, 지갑 사용 브라우저에서는 공식 저장소의 데이터 분실 안내 경고가 있었다.

10분 뒤에는 심사 기한 만료가 정상이다. 과거 승인 기록은 계속 조회되지만 현재 유효한 인증으로 표시하지 않는다. 로컬 체인을 초기화하면 위 주소와 거래는 더 이상 조회되지 않을 수 있다.
