# Midnight 네트워크 실행 안내

## 대상 네트워크

사용자 요청에 따라 개발 네트워크만 대상으로 진행한다. `undeployed`는 로컬 검증용, `preprod`는 공유 시연·제출용 개발 네트워크다. 클라이언트의 네트워크 선택과 타입도 이 두 환경만 제공한다. 다음 작업은 Preprod 테스트 지갑·테스트 잔액 준비와 실제 지갑 승인 흐름 연결이며, 메인넷 준비는 완료 조건이 아니다.

## 구현된 연결 경로

- `/`: 기존 가상 사용자 시뮬레이터. 브라우저별 상태가 독립되어 있다.
- `/network`: Midnight 개발 네트워크 클라이언트. 기본 연결은 로컬 개발 네트워크(`undeployed`)이며 실패 시 시뮬레이터로 자동 전환하지 않는다.
- 학생·학교: Connector 4.x 지갑과 사용자 암호로 개인 저장소를 연다. 기기 IndexedDB의 암호화된 상태는 네트워크·역할·지갑·배포 주소별로 분리된다.
- 학생의 commitment만 학교에 전달한다. 전체 공개 트리에서 학생 기기가 경로를 계산한다.
- 발급·사용은 Midnight.js의 `callTx` 결과로 확정을 확인한다.
- 식당: 지갑·개인 상태 없이 공개 인덱서로 동일 컨트랙트를 조회한다.
- 이 클라이언트는 loopback proof-server만 허용한다. 비밀 witness는 로컬 증명 서버로 전달되지만 학교 서버에 전달하지 않는다.

## 실행

```bash
npm ci
npm run contract:compile  # 첫 설치에서 키/회로 파일이 없으면 필요
npm run assets:copy
npm run network:up
npm run dev
```

로컬 체인은 `infra/compose.yml`의 노드 1.0.0, 인덱서 4.3.3, proof-server 8.1.0 조합을 사용한다. 공개 포트는 loopback 9944/8088/6300이다. 이는 공식 midnight-local-dev의 로컬 조합이며 Preprod 서버 버전과 구별한다.

Rancher Desktop 사용 시 `docker --context rancher-desktop compose -p quietpass -f infra/compose.yml up -d`를 사용할 수 있다. 종료할 때 동일 명령의 `up -d`를 `down`으로 바꾼다. 다른 프로젝트의 컨테이너는 조작하지 않는다. 로컬 노드 데이터는 이 MVP에서 영구 보관하지 않으므로 컨테이너 삭제 시 다시 배포해야 한다.

현재 작업 중 확인 URL: `http://127.0.0.1:4174/network`. 기본 실행 포트는 4173이다.

## 지갑으로 시연

1. 학교 브라우저에서 학교 역할·네트워크 선택 → 새 보관 암호(16자 이상, 문자/숫자/기호 조합) → 지갑 연결 → 새 프로그램 배포.
2. 확정된 프로그램 주소를 학생 브라우저와 식당 화면에 전달.
3. 학생 브라우저에서 학생 역할·같은 네트워크 선택 → 지갑·개인 보관함 연결 → 프로그램 연결. 학생 비밀키가 이 기기에서 생성된다.
4. 학생의 자격 등록값(commitment)만 학교로 전달. 모의 명부 DEMO-001 또는 DEMO-002에 연결하여 발급.
5. 학생 상태 새로 확인 → 캠퍼스 키친 사용 → 체인 확정 대기.
6. 식당 화면에서 같은 주소의 공개 원장 확인. 이름·학번·비밀 없이 사용 기록 조회.
7. 학생이 그린 테이블에서 다시 요청하면 거절. 미발급 학생도 거절.
8. 새로고침 후 같은 지갑·네트워크·주소·암호로 연결하면 기존 학생 비밀키를 다시 사용.

로컬 네트워크의 지갑에는 테스트 NIGHT와 DUST가 필요하다. Preprod에는 별도 테스트 지갑과 faucet 준비가 필요하다. 사용자의 지갑 승인이나 시드는 자동 입력하지 않는다.

## 실제 로컬 체인 자동 검사

```bash
npm run network:smoke
```

로컬 노드가 실행 중이어야 한다. 공개된 개발용 genesis seed로만 거래 수수료를 마련한다. 스크립트의 네트워크는 `undeployed`로 고정되어 있다. 생성된 학생·학교 비밀은 메모리에만 두며 결과 파일에는 공개 배포 주소·거래 해시·검사 결과만 기록한다.

이 검사는 실제 proof-server와 노드에서 발급·사용을 검증한다. 테스트 프로세스 안에 분리된 역할 상태와 하나의 개발용 수수료 지갑을 사용한다. 따라서 브라우저 지갑 승인, 독립 기기 간 거래, Preprod 검증과는 구별한다. 실패 거래 검사는 SDK 회로 실행에서 제출 전에 거절된 것인지 명시한다.

## 구현 경계

- 학교 명부는 학교의 암호화된 개인 저장소에 있다. 다른 브라우저에서 별도 발급키를 복원하여 우회하는 운영 문제는 해결하지 않는다. 운영용 학교 인증/중복 발급 DB가 아니다.
- 발급 실패가 불확실하면 학생의 등록값 예약을 유지한다. 다른 등록값으로 재발급하지 말고 공개 원장을 먼저 확인한다.
- 로컬 proof-server만 허용하므로 모바일 단독 증명은 현재 지원하지 않는다.
- 자격 철회·프로그램 종료·키 복구·결제·정산은 없다.
- 공개 시각·식당·프로그램·지갑 등 메타데이터로 연결 가능성이 있다. 완전 익명을 주장하지 않는다.
- 실제 확정 결과를 검증하기 전에는 거래 요청을 승인으로 표시하지 않는다.

## 호환성 고정

Compiler 0.31.1, Compact runtime 0.16.0, Midnight.js 4.1.1, Connector 4.0.1, onchain-runtime-v3 **3.0.0**.

`compact-runtime`의 허용 범위 때문에 3.1.1과 프로토콜의 3.0.0이 함께 설치되면 `expected instance of StateValue`가 발생한다. `package.json`의 직접 의존성과 override는 3.0.0을 단일 경로에 설치하도록 고정한다. 버전만 같아도 별도 디렉터리에 두 번 설치되면 객체가 호환되지 않는다. SDK 업데이트 시 실제 체인 검사로 다시 검증한다.
