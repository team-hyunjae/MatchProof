# MatchProof 실행 안내

가상 자료를 사용하는 Midnight Local Devnet(`undeployed`) 시연 앱입니다. 네트워크 연결 실패 시 시뮬레이터로 자동 전환하지 않습니다.

## 설치와 기본 실행

Node.js 22.12 이상, npm, unzip, Docker Compose가 필요합니다. 저장소를 받은 폴더에서 실행합니다.

```sh
npm ci
npm run setup:compiler
npm run contract:compile
npm run matchproof:compile
npm run network:up
npm run doctor:network
npm run demo
```

`MatchProof DEMO READY`를 확인한 뒤 [앱](http://127.0.0.1:4180/matchproof)을 엽니다. `npm run demo`는 빌드, 공식 개발용 지갑 어댑터, 웹 서버를 실행합니다. 별도 지갑 확장이나 수동 스크립트 주입은 필요하지 않습니다. 개발 거래는 자동 서명되며 확장 지갑 승인창은 나타나지 않습니다.

개발 서비스가 준비되기 전에 `doctor:network`가 실패하면 서비스 준비 후 다시 실행합니다. 4180·4181 포트를 사용하는 이전 preview/demo가 있다면 해당 프로세스를 종료합니다. 다른 프로세스를 임의 종료하지 않습니다.

실행 터미널을 유지합니다. 지갑 준비 완료 후 30분에 세션이 종료되면 `npm run demo`를 다시 시작하고 페이지를 새로고침합니다. 같은 개발 지갑을 사용하는 `matchproof:smoke`와 동시에 실행하지 않습니다.

## 구성과 보관함

| 서비스 | 기본 주소 |
| --- | --- |
| Midnight 노드 | `http://127.0.0.1:9944` |
| 인덱서 | `http://127.0.0.1:8088` |
| 증명 서버 | `http://127.0.0.1:6300` |
| 데모 웹 앱 | `http://127.0.0.1:4180/matchproof` |

포트가 SSH 터널이면 실제 서버는 다른 기기에 있을 수 있습니다. 증명 서버는 비공개 입력을 처리합니다. `127.0.0.1` 주소는 접속하는 사람의 컴퓨터를 가리키므로 외부 심사위원에게 제공할 공개 데모 URL이 아닙니다.

역할별 화면에서 보관 암호를 입력하고 **개발용 지갑 연결**을 누릅니다. 신규 암호는 16자 이상이며 대문자·소문자·숫자·기호 중 3종류 이상을 포함합니다. 기존 보관함은 같은 암호로 연결합니다. 암호는 지갑 복구 구문이 아닙니다.

개인 상태는 네트워크·역할·지갑·배포 주소별로 암호화한 IndexedDB에 저장합니다. 브라우저 데이터나 암호를 잃었을 때의 복구 기능은 없습니다. 같은 역할의 여러 탭에서 동시에 거래하지 않습니다.

## 새 배포에서의 순서

1. **업체:** 보관함을 연결하고 업체 등록값을 기관에 전달합니다. 처음에는 배포 주소가 없어도 됩니다.
2. **모의 검증기관:** 업체 등록값으로 계약을 배포하고, 확정된 주소를 업체와 신청자에게 전달합니다.
3. **신청자:** 같은 배포에 연결하여 신청자 등록값을 기관·업체에 전달합니다. 비밀키는 전달하지 않습니다.
4. **모의 검증기관:** 신청자 등록값과 가상 자료를 선택해 자격을 발급합니다. 확정 후 자격 JSON을 해당 신청자에게만 전달합니다.
5. **신청자:** 자격을 가져옵니다. 앱은 신청자 키와 등록 commitment의 일치를 확인합니다.
6. **업체:** `DEMO-001` 같은 가상 접수번호와 신청자 등록값으로 요청을 생성합니다. 확정 후 요청 JSON을 신청자에게 전달합니다.
7. **신청자:** 요청을 가져오고 수신 업체·조건·공개 범위·기한을 확인합니다. 명시적 동의 후 증명을 시작합니다. 테스트 지갑은 자동 서명하며, 앱은 체인 확정 후 성공을 표시합니다.
8. **업체·심사위원:** 최신 상태 또는 별도 업체 화면에서 같은 요청의 공개 결과를 조회합니다. 공개 조회에는 지갑이나 신청자 파일이 필요하지 않습니다.

요청은 최대 10분 동안 유효합니다. 요청 생성 거래가 오래 지연되면 생성 시간 검사에 실패할 수 있습니다. 제출이 시작된 뒤 오류가 발생했다면 먼저 공개 기록에서 확정 여부를 확인합니다. 만료된 요청은 새로 만들어야 합니다.

자격 JSON에는 정확한 가상 소득·혼인 상태·salt가, 요청 JSON에는 private nonce가 포함됩니다. 공개 게시하지 않습니다. 파일 가져오기는 브라우저에서 처리하지만, 이후 증명 생성 단계에서 증명 서버로 비공개 입력을 전달합니다.

상세 버튼 순서와 실패 사례는 [한국어 시연 가이드](matchproof-judge-guide.md)와 [영어 시연 가이드](matchproof-judge-guide.en.md)를 참고합니다.

## 기존 배포 조회

배포 주소를 입력하고 **체인 기록 조회**를 누릅니다. **최근 시연 불러오기**는 마지막 CLI smoke 실행이 만든 locator를 사용합니다. 새 clone이나 브라우저에서 직접 배포한 계약의 주소는 자동 등록되지 않으므로 직접 입력하거나 **별도 업체 화면 열기**를 사용합니다.

과거 승인도 기한이 지나면 **기한 만료**로 표시됩니다. 체인 기록은 유지되지만 개발 체인을 초기화하면 기존 배포를 더 이상 조회할 수 없습니다.

## 일반 개발 서버와 확장 지갑

`npm run dev`는 4173 포트에서 개발 서버를, `npm run build` 후 `npm run preview`는 4180 포트에서 빌드된 앱을 실행합니다. 두 경로에는 개발용 테스트 지갑을 자동 주입하지 않습니다. 이미 확정된 기록의 공개 조회는 지갑 없이 가능합니다.

이 경로에서 새 거래를 만들려면 Connector 4.x를 지원하는 Midnight 지갑, `undeployed` 네트워크 설정과 개발용 잔액이 필요합니다. 확장 지갑 경로는 테스트 지갑 데모와 구분하며 실제 확장 승인창 검증 완료를 주장하지 않습니다. MatchProof는 Mainnet·Preprod로 연결하지 않습니다.
