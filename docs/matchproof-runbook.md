# MatchProof 개발 네트워크 시연

`/matchproof`는 새 결혼정보 심사 클라이언트다. 가상 자료만 사용하며 네트워크는 **로컬 `undeployed`**로 고정한다. 연결 실패 시 시뮬레이터로 전환하지 않는다.

## 수동 시연을 바로 시작 — 2026-09-26 추가

프로젝트 폴더는 `~/devel/ai/MatchProof`다. 개발 서비스가 실행 중인 상태에서 `npm run doctor:network` 후 `npm run demo`를 실행한다. `DEMO READY`가 나오면 `http://127.0.0.1:4180/matchproof`를 연다. 이 명령은 공식 개발 지갑 어댑터와 웹 서버를 함께 실행하고, 해당 시연 페이지에만 Connector 4.x를 제공한다. 별도의 확장 설치나 수동 스크립트 주입이 필요 없다. 개발 거래는 자동 서명되며 화면에 테스트 지갑임을 표시한다.

기존 preview가 4180을 쓰면 먼저 그 프로세스를 종료한다. 같은 genesis 지갑을 쓰는 smoke와 동시에 실행하지 않는다. 시연 준비 후 30분에 지갑·웹 서버가 종료되므로 필요하면 다시 시작한다. 일반 `npm run dev`/`preview`에는 이 연결을 넣지 않는다.

아래 지갑 확장 안내는 확장으로 실행하는 대안 경로다. `demo` 경로는 확장 승인창을 검증하지 않는다. 2026-09-26 현재 loopback 개발 포트는 SSH 터널이 사용 중이므로 실제 증명 서버가 같은 물리 기기에 있다고 단정하지 않는다.

## 준비

기존 프로젝트의 Node·Compact 0.31.1 설치를 사용한다. 네트워크는 `infra/compose.yml`의 로컬 노드(9944), 인덱서(8088), proof-server(6300)다.

```sh
npm install
npm run contract:compile
npm run matchproof:compile
npm run network:up
npm run dev
```

Rancher Desktop Docker context가 필요한 환경은 `docker --context rancher-desktop compose -p quietpass -f infra/compose.yml up -d`를 사용한다. `npm run dev` 기본 주소는 `http://127.0.0.1:4173/matchproof`다. 다른 포트는 `PORT=4174 npm run dev`처럼 지정한다.

빌드한 화면을 `http://127.0.0.1:4180/matchproof`에서 보려면 다음을 실행한다.

```sh
npm run build
npm run preview
```

이 주소는 로컬 미리보기 서버가 실행되는 동안만 열린다. 서버를 종료했거나 컴퓨터를 다시 시작했다면 프로젝트 폴더에서 `npm run preview`를 다시 실행한다. 기존 빌드가 있고 소스 변경이 없다면 다시 빌드할 필요는 없다. 페이지는 열리지만 체인 조회가 실패한다면 개발 네트워크 인덱서(8088)가 실행 중인지 확인한다.

브라우저는 Connector 4.x를 지원하는 Midnight 지갑을 사용한다. 지갑 네트워크는 `undeployed`, 인덱서는 로컬 8088 포트, 증명 서버는 신청자 기기의 loopback 주소를 사용한다. 개발용 NIGHT/DUST 잔액이 필요하다. 메인넷·Preprod 지갑은 이 클라이언트가 연결하지 않는다.

개인 상태는 네트워크·역할·지갑·배포 주소별로 암호화하여 IndexedDB에 저장한다. 암호는 16자 이상, 대문자·소문자·숫자·기호 중 3종류 이상을 쓴다. 브라우저 데이터·암호 분실 복구는 이 버전에서 제공하지 않는다. 역할별로 별도 브라우저 프로필을 권장하며, 같은 역할의 여러 탭에서 동시에 거래하지 않는다.

## 지갑 없이 이미 확정된 기록 보기

`npm run matchproof:smoke`를 먼저 실행한 환경에서 업체 탭의 **최근 시연 불러오기**를 누른다. 공개 주소 파일은 조회 대상을 찾는 용도이며 결과는 브라우저가 인덱서에서 직접 읽는다. 새 실행으로 locator가 바뀌면 production preview는 `npm run build`로 다시 만든다. 개발 서버는 `public/`의 새 locator를 바로 읽는다.

수동으로 배포 주소를 입력하고 **체인 기록 조회**를 눌러도 된다. 이 조회에는 지갑, 자격증명 파일, 신청자 비밀키가 필요하지 않다. 조회로 보이는 공개 요청 식별값은 업체의 실제 회원 이름이 아니다. 기한이 지나면 과거 승인 기록도 **기한 만료**로 표시한다.

## 브라우저에서 처음부터 실행

1. **업체:** 지갑과 보관함을 연결한다. 업체 등록값을 검증기관에 전달한다. 이 값에는 비밀키가 없다.
2. **모의 검증기관:** 별도 역할로 지갑을 연결하고 업체 등록값을 입력하여 배포한다. 확정된 배포 주소를 업체와 신청자에게 전달한다.
3. **신청자:** 해당 배포에 연결한다. 배포별 신청자 키를 기기에서 생성한다. 신청자 등록값을 검증기관과 업체에 전달한다.
4. **모의 검증기관:** 배포에 연결하고 신청자 등록값·가상 자료 유형을 선택해 발급한다. 확정 후 자격증명 JSON을 다운로드하여 해당 신청자에게만 전달한다. 같은 자료의 파일 재다운로드에는 발급 기록을 재사용한다.
5. **신청자:** 자격증명 파일을 가져온다. 파일은 브라우저에서 파싱하고 신청자 키와 실제 등록 commitment가 일치하는지 검사한다. 서버 업로드는 하지 않는다.
6. **업체:** 해당 배포에 연결하고 `DEMO-001` 같은 가상 접수번호와 신청자 등록값으로 심사 요청을 만든다. 확정 후 요청 JSON을 해당 신청자에게 전달한다. 요청은 최대 10분 동안 유효하다.
7. **신청자:** 요청 파일을 가져온다. 업체 등록값, 소득·혼인 조건, 기간, 공개 결과를 확인한다. 동의 체크 후 증명 버튼을 누르고 지갑에서 개발용 거래를 승인한다. 확정 전에는 완료로 표시하지 않는다.
8. **업체:** 최신 상태를 조회한다. 동일 요청에 대해 조건 충족이 표시되는지 확인한다. 다른 브라우저의 별도 업체 화면에서도 공개 인덱서로 확인할 수 있다.

요청 생성 시 거래가 오래 지연되면 60초 생성 구간 검사가 실패할 수 있다. 원장에서 제출 결과부터 확인한 후 새 요청을 만든다. 신청자가 증명을 제출하기 전에 10분이 지나도 새 요청이 필요하다.

JSON 파일은 실제 서비스의 안전한 자격 전달 채널을 대신하는 **가상 자료 수동 전달**이다. 자격증명 파일에는 정확한 가상 소득·혼인 상태·발급 salt가, 요청 파일에는 비공개 nonce가 포함된다. 공개 게시·URL 공유 용도로 쓰지 않는다. 신청자 비밀키는 어느 파일에도 포함하지 않는다.

## 검증 명령과 증거

```sh
npm run typecheck
npm test
npm run build
npm run matchproof:smoke
```

`matchproof:smoke`는 가상 자료, 역할별 개인 상태, 공개 개발용 수수료 지갑 하나를 사용해 브라우저와 같은 `MatchClient`를 실행한다. 새 계약 배포, 발급, 요청 등록, ZK 증명 확정, 재사용 거절, 다른 신청자의 파일 수입 거절, 소득 미달 거절, 별도 인덱서 조회를 확인한다.

결과는 `artifacts/matchproof-smoke.json`에 공개 거래 정보만 저장한다. `public/matchproof-demo.json`에는 조회 주소와 공개 요청 식별값만 들어간다. 두 파일 모두 Git에서 제외한다. 실패 검사는 **제출 전 SDK 회로 실행/파일 검사에서 거절**된 것이며, 실패 거래가 체인에서 채굴됐다고 표현하지 않는다.

실행한 거래 주소·브라우저 확인 결과·남은 검증은 [검증 기록](matchproof-verification.md)에 있다.

## 브라우저 통합 검사용 개발 지갑

`scripts/matchproof-browser-wallet.ts`는 개발 네트워크 전용 검사 도구다. 공식 `DAppConnectorWalletAdapter`와 공개 local genesis 지갑을 사용한다. 브라우저 확장의 사용자 승인창을 대체하는 테스트 어댑터이며 사용자 지갑을 열거나 복구 구문을 읽지 않는다.

```sh
npm run preview
# 별도 터미널에서 실행
node --import tsx scripts/matchproof-browser-wallet.ts
```

이 도구는 `127.0.0.1:4181`에만 바인딩하고, origin `http://127.0.0.1:4180`과 실행별 난수를 검사한다. Playwright가 `artifacts/browser-wallet-connector.js`를 init script로 설치한 테스트 브라우저에서만 사용한다. 앱은 이 파일을 자동 로드하지 않는다. 파일은 테스트 접근 정보를 포함하므로 배포·커밋하지 않는다. 검증 후 프로세스를 종료하며 30분 뒤에도 자동 종료한다.

## 현재 한계

- 모의 검증기관이며 실제 소득·혼인 서류와 연동하지 않는다.
- 접수번호와 요청의 대응관계는 업체 기기의 암호화 상태에 있다. 실제 회원 로그인·서버 세션·직원 권한 시스템은 아직 없다.
- '확인 기준일에 혼인 중이 아님'을 증명한다. 현재 혼인 상태나 과거 혼인 이력의 부재를 보증하지 않는다.
- 공개 정책·시각·요청·성공 거래가 계정이나 지갑과 연결되면 조건 충족 사실이 드러날 수 있다.
- 로컬 proof-server는 비공개 증명 입력을 받는다. '브라우저 밖으로 전혀 나가지 않음'이 아니라 '신청자 기기의 로컬 서버에서 증명'하는 모델이다.
- 개인키 대여, 같은 실제 사람의 중복 계정, 즉시 철회, 데이터 분실 복구는 해결하지 않는다.
